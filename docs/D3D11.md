# Direct3D 11 (Windows)

[Docs index](README.md) › Direct3D 11

The inspector captures Direct3D 11 applications on Windows. Direct3D 11 support is a
[plugin](PLUGINS.md), like OpenGL ES, and comes with the app; it does less than the built-in
Direct3D 12 support does, and [what is not there yet](#what-is-not-there-yet) has the list.

## Launching an application

Press **Launch...** and choose the executable, as for a [Vulkan](VULKAN.md) or
[Direct3D 12](D3D12.md) application. Every Windows target is started with the Direct3D 11 capture
library injected beside the others, and it connects when the application makes a swap chain for a
Direct3D 11 device. The session's **Log** tab names each library that went in. **Wait for
application** works the same way for an application started by something else, as does
`--launch=<exe>` on the command line.

Two kinds of Direct3D 11 device are deliberately not captured, so the library does not take the
session's port from the API you meant to see: a device made by ANGLE's `libGLESv2.dll`, which is
an [OpenGL ES](GLES.md) application on ANGLE's Direct3D 11 backend (`D3D11INSP_ANGLE=1` in the
launch's environment captures it as Direct3D 11 instead), and a device that never gets a swap
chain, such as one an application makes for video decoding.

A Unity player takes `-force-d3d11`; a Unreal Engine game takes `-d3d11` or `-dx11`.

## What a capture shows

Direct3D 11 has no command buffers on the immediate context and no render passes, so a capture is
the calls the application made between two `Present`s, per device context. The capture library
marks a pass wherever the render targets change (`BeginRenderPass` and `EndRenderPass`, which are
not Direct3D calls), and each pass's color and depth targets are read back as it ends. Events
(`ID3DUserDefinedAnnotation::BeginEvent`, what PIX markers are) nest the command tree as debug
labels do for the other APIs. A deferred context's command list appears inlined under the
`ExecuteCommandList` that ran it, the way a Vulkan secondary command buffer does.

Selecting a draw shows the state that was in effect when it ran, since in Direct3D 11 that is the
context's state rather than anything bound on a command:

- the **shaders** of each stage, with their disassembly and reflection;
- the **vertex input**: the input layout's elements with their buffers, formats, offsets and strides,
  the bytes the draw read, and the index buffer for an indexed draw;
- each stage's **constant buffers**, decoded by the shader's reflection, **shader resources** with
  their contents, and **samplers**;
- the **unordered access views** a dispatch or a pixel shader writes;
- the **rasterizer, depth-stencil and blend** state and the **render targets**.

With **Profile passes** each pass is timed on the GPU (timestamp queries), which gives Frame Stats
its Frame Bound verdict and pass list; the passes of a deferred context are not timed.

The textures and buffers a draw uses are copied on the GPU where the draw is met and read once the
frame is over, so a capture does not stall the frame it records.

**View Mesh** opens the draw's vertices, and the **Render Graph** shows the passes and what they
read from each other. It knows which targets a pass cleared before drawing and which it discarded
(`DiscardView`), so its suggestions about unread results hold for Direct3D 11 too. Capture files
save and reopen as for any API, and the [Claude Code plugin](MCP.md) reads them.

## Testing it

`test/d3d11_triangle` (built with the rest, `d3d11insp_triangle.exe`) draws a textured cube into an
offscreen target and that target onto the swap chain; `--msaa`, `--deferred`, `--compute`,
`--discard` and `--debug-layer` exercise the rest of the library.

## What is not there yet

- No replay: overdraw, draw overlays, pixel history, per-draw measurements and Export to C++.
- No shader debugger, shader analysis or shader editing: DXBC has no source form the debugger runs.
- Multisampled depth targets are not read back, and a deferred context's passes are not timed.
- Shared resources and Direct3D 11-on-12 devices are not tracked.

`src/plugins/d3d11/README.md` has how the library does what it does.
